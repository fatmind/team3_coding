# Habits

## Habit: 读持久化值，不重新计算
- **描述**: 人类在发现"同一个值被不同代码用不同算法算出不一样结果"的 bug 后，定下规矩：凡是启动时算好并存到文件的值（端口、ID、PID 等），下游一律从文件读，不许自己再算一遍。重算 = 埋雷。
- **证据**:
  - 2026-06-01: "两套算法产出不同端口，ChatPanel 连到了空端口"
  - 2026-06-01: "凡是启动时计算并持久化的值（端口、session ID、PID），下游一律从持久化文件读，不重新派生"

## Habit: 不在下游硬编码上游的格式假设
- **描述**: 人类发现 Web 层用正则 `/^module_\d+$/` 校验 Module ID、结果把 Arch 创建的语义化 ID 全拒了之后，明确表态：ID 格式由创建方决定，消费方不该写死格式约束。
- **证据**:
  - 2026-06-01: "Module ID 格式由 Arch agent 在运行时决定，Web 层不应硬编码格式假设"

## Habit: 利用工具原生机制，不自建服务
- **描述**: 人类在做技术选型时，反复选择"用工具自带的配置/注入方式"而不是自己搭一套 API 或 HTTP 服务。能用 CLAUDE.md / .cursorrules 搞定的事，就不多写一层接口。
- **证据**:
  - 2026-06-10: "通过工具原生机制（CLAUDE.md / .cursorrules）写入，不做 API/HTTP 服务"
  - 2026-06-10: "利用工具原生配置机制自动注入：Claude Code 用 session_start hook 写 CLAUDE.md，Cursor 写 .cursorrules。不做 API 接口"

## Habit: MVP 砍到最小，能不做就不做
- **描述**: 人类在规划迭代范围时，反复把初始设计大幅收窄——砍 Dashboard、砍前端、砍不紧急的功能模块，只保留最核心的链路先跑通。
- **证据**:
  - 2026-06-10: "MVP 范围：2 个 Collector（Claude Code + Cursor）+ Distiller + 动态 Injector。不做 Dashboard，不做 Scheduler"
  - 2026-06-10: "MVP 无前端，纯 Node.js CLI 工具（原设计是 Next.js 全栈，但 Dashboard 不在 MVP 范围）"
  - 2026-07-18: "本次范围只到「出机会卡片」为止……回测台（§2.3 / §4.4）留后续 module，本 module 不做命中/评分"

## Habit: 方案不可靠就果断换，不纠缠沉没成本
- **描述**: 人类发现已派发的技术方案（pytrends）频繁 429、字段不稳定后，没有让团队继续修补，而是直接弃用、切换技术路线、统一技术栈。
- **证据**:
  - 2026-07-15: "pytrends 走非官方接口、频繁 429/字段不稳定，不靠谱，弃用。Google Trends 改用 webclaw3 skill pipeline 做浏览器自动化采集，全项目技术栈统一为 nodejs"

## Habit: 脚本算事实，LLM 做判断——两者不越界
- **描述**: 人类在审阅产出时，发现脚本用模板写了"为什么值得做"这类研判文案后非常不满，明确划界：脚本/代码只做确定性计算和事实搬运，所有需要判断、推理、下结论的活儿一律交给 LLM。
- **证据**:
  - 2026-07-16: "脚本只算事实、只 copy 真实外部需求，不做候选分流、不下新星/衰退结论、不写'为什么值得做'、不给优先级、不做研判"
  - 2026-07-17: "不做机械三涨跌分流脚本……§2.2.2 的新星/衰退/缺失分类并入 LLM 研判提示词，由 LLM 结合三轴事实卡判断"
  - 2026-07-18: "§2.2.2 三类分类在 Module 3 只作 prompt 指导语、非脚本分支"

## Habit: 数据诚实标注来源，不混淆真假
- **描述**: 人类在 mock 数据和真实数据共存时，要求证据卡必须显式标注每条数据的来源（真实 / mock），不允许把 mock 数据伪装成真实数据，也不允许因为"暂时没数据"就留空或含糊。
- **证据**:
  - 2026-07-16: "证据卡必须显式标注真 vs mock——外部需求=Module 1 真实(快照，不写方向)，Lazada 站内=mock"
  - 2026-07-17: "竞对与 Lazada 站内对称地 mock、对称标 source=mock。诚实底线不变——mock 就明确标 mock、不臆造成真实竞对表现"

## Habit: 宁可标注缺失也不编造
- **描述**: 人类在面对数据匹配不上的情况时，选择如实标注"无对应外部需求信号"作为事实，而不是强行凑出结论或编造关联。
- **证据**:
  - 2026-07-16: "匹配零需求→如实标'无对应外部需求信号'；需求无对应簇→进'站内缺失该需求'事实清单（当事实，不下'缺失商品'结论——结论属 4.3）"

## Habit: Mock 做成可复用能力，不是一次性脚本
- **描述**: 人类在要求做 mock 数据时，明确 mock 不是"为当前类目写一次性脚本"，而是要设计成按类目可配置、可复用的能力——因为后续会换很多类目反复验证。
- **证据**:
  - 2026-07-16: "mock 数据层必须按叶子类目可配置、可复用（已写进 module2.md §2.1 + Feature #1 checkpoint Step4 可扩展性 smoke）"
  - 2026-07-17: "Module 2 的本质是「mock 能力/引擎」不是「一次性数据」……后续要大批量造 mock 数据（更多类目/国家/数据轴）"
