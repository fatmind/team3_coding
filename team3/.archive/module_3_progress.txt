### Feature #22: Agent stdout stream-json 解析 + WS 广播 (2026-06-06)

**实现功能**：
- 新建 `stdout-parser.js` 模块，解析 claude code `--output-format stream-json` 的**真实格式** stdout 行：
  - 真实格式：`{type:"assistant", message:{content:[{type:"text"|"thinking"|"tool_use", ...}]}}`
  - 数据位置：text→`block.text`，thinking→`block.thinking`（非 block.text），tool_use→`block.name`+`block.input`
  - `thinking` → `[思考] + 截断500字符`（Module 1 #10 调优后 daemon/web 同步）
  - `text` → `截断500字符`，含 `✓`/`passed` 时 tone=success，含 `→` + action 关键词时 tone=mention
  - `tool_use` → `name + 参数摘要（file_path > command > description > query）`，tone=route
  - `system/user/result` → null，跳过
  - 新增 `parseContentBlock()` 解析 message.content[] 中的单个 block
- AgentScheduler 集成：
  - Per-role 行缓冲（`_lineBuffers`）：`\n` 切分，保留 partial line 等下一个 chunk
  - `_processStdoutChunk(role, chunk)`：拆完整行 → `parseStreamJsonLine()` → 非空结果 emit `agent-log` 事件
  - 进程 close 时清空行缓冲
- DaemonOrchestrator 集成：
  - 监听 `agent-log` 事件 → `daemon.broadcast()` 推送 WS 事件 `{type:'agent.log', role, lines:[{content, tone?}]}`

**发现并修复的问题**：
- 首版基于错误的 stream-json 格式（`{type:"assistant", subtype:"text", content:"..."}`），与真实 claude code 输出不匹配
- 真实格式无 subtype 字段，数据嵌套在 `message.content[]` 数组中，每个 block 的字段名也不同（thinking 用 `block.thinking` 而非 `block.text`）
- 参考 `example/badminton_call/logs/arch_2026-06-04.log` 的真实 JSON 结构完全重写 parser + 全部单测

  - 非零退出 → 5s 后重启，连续 5 次失败则停止并输出错误信息

- Daemon graceful shutdown：
  - `stop()` 中先调用 `clearAllTimers()` + `killAllProcesses()`

### Feature #15: ActionWatcher offset 持久化 + Daemon 重启 Replay (2026-05-28)

**实现功能**：
- 新建 `state-persistence.js` 模块，封装 `.daemon-state.json` 的读写：
  - `load()`：从文件读取持久化状态（lastProcessingOffset/spawnedPids/lastUpdated），文件不存在或损坏返回默认值
  - `updateOffset(offset)`：更新 lastProcessingOffset，debounce 200ms 写入文件
  - `updatePid(role, pid)`：更新 spawnedPids，debounce 写入
  - `saveSync()`：立即同步写入（取消 pending debounce timer）
  - `destroy()`：取消 pending timer，释放资源
- ActionWatcher 增加 replay 能力：
  - 新增 `initialOffset` 构造参数：启动时从指定偏移开始读取（而非默认跳到文件末尾）
  - 新增 `onOffsetUpdate` 回调：每次 emit action 后通知当前偏移量
  - `start()` 时若 `initialOffset < fileSize`，立即读取并 replay 被跳过的内容
  - `initialOffset > fileSize` 时（文件截断），自动 reset 到 0 从头读取
- DaemonOrchestrator 集成：
  - 构造时创建 StatePersistence，load() 读取持久化 offset
  - 将 persisted offset 传入 ActionWatcher（initialOffset），onOffsetUpdate 回调更新 StatePersistence
  - 先 wire listener（on('action')）再 start() watcher，确保 replay 事件不丢失
  - stop() 时同步写入最终 offset（saveSync）并 destroy

### Feature #13: Claude 进程超时 Kill + 异常退出重试 + Dead Letter 通知 (2026-05-27)

**实现功能**：
- spawn claude 后启动可配置超时 timer（默认 30 分钟，通过 CLAUDE_TIMEOUT_MS 环境变量配置）
- 超时处理：SIGTERM → 等 5s grace period → SIGKILL → 标记为超时退出
- 正确处理 signal-killed 进程（code=null, signal='SIGTERM'/'SIGKILL'）作为非零退出
- 非零退出（含超时 kill）时，本次 messages prepend 回队列头部，delay 5s 后重新执行
- 消息携带 _retryCount 标记，跨重试传递，避免无限循环

- Dead Letter 后该 Agent 队列恢复 idle，后续新消息正常处理
- spawn error（如 ENOENT）同样走 retry → dead letter 流程
- 提供 clearAllTimers() 方法供优雅关停
